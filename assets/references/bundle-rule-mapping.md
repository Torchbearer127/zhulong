# Bundle Contract Rule Mapping

This mapping keeps the P8 bundle contract aligned with the renderer, builder,
final validators, and bundle evidence artifacts.

## Purpose And Boundary

Contract preflight means `ready to render`: the selected finding has the
portable, single-vulnerability, Docker-backed inputs needed for the staging
builder to render reviewer-facing artifacts.

Contract preflight is a generation readiness workflow gate. It does not prove a
vulnerability and does not replace Docker evidence, `validate_report_bundle.py`,
`validate_all_report_bundles.py`, seeded variant discovery, or finalization.
Confirmed status still requires Docker evidence plus final confirmed-bundle
validation.

## Severity And Bug Class Policy

`finding.severity` uses a stable enum in the bundle contract:
`Critical`, `High`, `Medium`, `Low`, and `Informational`. The contract stores
these English labels so preflight fixtures, builder inputs, and validators agree
on one machine-readable severity vocabulary; renderers and final reports may
localize the displayed label while preserving the same meaning.

`finding.bug_class` and `impact_tier.bug_class` remain free text. Vulnerability
classes are open-ended across languages, frameworks, and project-specific
boundaries, so a strict enum would reject useful labels such as library-specific
loader flaws or compound classes. The generation checklist records recommended
bug classes for consistency, including `SSRF`, `Path Traversal`,
`Prototype Pollution`, `Command Injection`, `Deserialization`,
`Authentication Bypass`, `Authorization Bypass`, `Information Disclosure`, and
`Denial of Service`; class text alone must not imply stronger impact or
confirmation.

| `bundle.slug` | Selects one stable bundle directory name. | Builder requires renderer output directory to match the slug before staging. | Final validator checks one bundle directory and stable output filenames. | `confirmed/<slug>/` | Must not be used to group multiple vulnerabilities. |
| `bundle.language` | Selects reviewer-facing report language. | Renderer writes localized DOCX, supplement, and attachment index. | Final validator checks language-specific headings and untranslated-text drift. | DOCX report, reproduction supplement, attachment index | Language is presentation scope, not severity or impact evidence. |

## Maintenance Rule

Any new contract field must be added to this mapping in the same change. If a
field cannot map to renderer output, a final validator or batch gate, and a
bundle evidence artifact, do not add it to the contract.

When editing this file, preserve the boundary language: contract preflight is
`ready to render` / generation readiness only, while Docker evidence and final
confirmed-bundle validation remain required for confirmed status.
